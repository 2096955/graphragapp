Typed decisions for graph-based dataset discovery

Finding datasets in a catalogue takes many small calls: can this request be answered, which pollutants and breakdowns does it mean, how well does each dataset fit. This lab puts a decision model on each of those calls. Kuzu holds the two-layer graph. Jev is the typed decision layer, not the database — Catalogue rules, Laya, AnyJev and TypeSafe Jev answer the small fixed questions; the graph only proposes candidates. For a comparison of graph databases, open the field guide. This lab’s /api/compare compares decision backends, not those engines.

Why two hops are enough

The Watts–Strogatz figures are a synthetic N=500 visual, not a measurement of this catalogue graph. Token-bounded retrieval is the design claim, not a measured p95. The compliance filter only expands a short neighbourhood from the matched pattern for that reason.

Worked example: compliance filter

A legal and compliance agent sits in front of a research agent. Jev (or Catalogue rules when no key is set) decides release, redact or block. If the decision backend errors, the filter fails closed and blocks. Kuzu stores a hashed pattern identity, the decision, and the attempt count — not raw PII. The same pattern identity is a repeat; recording the same payload is idempotent. Arize is the eval and cost view: traces, whether the filter was right, and what the decision cost. Space name on the signed-in account is AzureDev. Send traces with register(space_id, api_key, project_name=...) or OTLP (https://otlp.arize.com/v1 gRPC, https://otlp.arize.com/v1/traces HTTP). A key named graph-demo must not be committed. There is no live Arize export unless the env vars are set. This example has no measured redaction precision and no retention policy.

The pipeline

The discovery method from Diamantini et al. (2026), with a decision model making each call. The graph proposes candidates and finds datasets; the model never writes text, and the explanation never makes a decision.

Can the probabilities be trusted?

Recorded model runs are legacy experiments on 448 decisions. The current test set also covers whole-group selection and preference scoring. Empirical coverage searches a threshold on the same labels; it is not a deployment error guarantee. Grouped holdout results keep threshold selection separate from evaluation.
